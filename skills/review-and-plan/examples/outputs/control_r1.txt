## Sprint plan

Order matters: verify before changing anything.

**Step 0, about 30 minutes: establish ground truth.**
- Install the package with its dev dependencies, then run `pytest -q` and `pytest --cov`.
- Record the real test count and coverage figure, and note any failures.
- Read `pyproject.toml` for the supported Python versions and the test dependencies.
- Exit criterion: you know whether the README numbers are true today.

**Step 1, highest value: make CI run the tests.**

- Run it on the Python versions that `pyproject.toml` declares.
- Exit criterion: a deliberately failing test turns CI red.

**Step 2: make the coverage claim enforceable.**
- Add `--cov` with `--cov-fail-under` set a little below the measured figure.
- Fix the README to the verified numbers, or replace the hard-coded numbers with a coverage badge.

**Step 3, optional: tighten the checks.**
- Add `ruff format --check`, and a type checker if the code is typed.
- Add a smoke test that builds the package and runs the CLI entry point with `--help`.

**Step 4, optional: docs and hygiene.**
- Check `docs/usage.md` against the real CLI output.
- Add a LICENSE or CHANGELOG only if the project will be shared.
