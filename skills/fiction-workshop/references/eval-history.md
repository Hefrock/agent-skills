# Fiction Workshop — smoke-test history

Moved verbatim out of `SKILL.md` so the skill's trigger-time file carries instructions, not history. Nothing below is an instruction to follow; it is the record of how the persona docs and agent files were tested and what was fixed.

**Status: skeleton, smoke-tested — all 18 routing-table personas individually exercised.** Persona routing table and command shapes are defined below; the six backing subagent definitions (`agents/story-*.md`) and the per-persona reference docs (`references/personas/*.md`) they draw on are written. A real smoke-test pass (2026-10-05, `examples/persona_eval_cases_v1.jsonl` / `persona_eval_results_v1.jsonl`) ran one case per persona, each probing that persona's specific documented scope/exclusion/isolation rule: a fresh, isolated subagent actually embodied the persona against a real scenario, its full transcript was committed (not a summary), and a separate grading pass scored it against that case's specific contract — validated against `agent-eval`'s real `score_eval.py` (`python score_eval.py persona_eval_results_v1.jsonl --ci`).

Result: **15/18 passed at a 0.7 threshold (mean 0.86, n=18 — directional, not precise).** Three real defects were found this way and are now fixed at the persona-doc level:
- Developmental Editor accepted smuggled Adversarial Beta Reader notes instead of refusing them — a direct Isolation-rule violation (score 0.0). Literary Agent asked the publishing-path question but didn't wait for the answer before proceeding (0.8) — same root cause: a precondition stated only at the orchestration layer, with no self-enforcement at the persona layer. Fixed by adding explicit self-enforcement language to every `story-critic`/`story-utility` persona doc and to Literary Agent.
- Marketing Copywriter invented comp titles from scratch when none were supplied, violating its own exclusion, and delivered them as a finished asset with no caveat visible anywhere except a post-hoc self-report (0.3). Fixed by adding explicit ask-first-or-flag-provisional guidance.
- Genre/Comp-title Expert rendered a quotation-marked fragment attributed to a real novel's opening line while its own self-report claimed full compliance with the copyright-hygiene guardrail (0.6) — the one case in this run where the self-report and the actual transcript disagreed, which is itself the reason grading is done by reading transcripts directly rather than trusting a persona's own compliance claim. Fixed by strengthening the guardrail in this persona's doc and in Research/Fact-Checker's (same guardrail, same risk).
- Also fixed: Story Architect's prose-handoff misattribution from the first 8 cases (correctly declined to write prose, but pointed to the wrong next persona) — re-tested clean in Character Psychologist's case this round.

Per-category breakdown: `story-planner` 100% (mean 0.95, n=5), `story-drafter`/`story-doctor`/`story-utility` 100% (n=1, n=1, n=3), `story-publisher` 75% (mean 0.78, n=4, dragged down by the Marketing Copywriter finding), `story-critic` 50% (mean 0.65, n=4, carrying both the Isolation-rule failure and the copyright partial-miss) — the real signal concentrates exactly where the isolation/copyright/missing-input failure modes live, not spread evenly.

**Fix confirmation (2026-10-05, same day, fw_019–fw_023):** writing a doc fix and moving on without re-running the exact failing case against it is the same claims-vs-reality gap this whole exercise exists to catch, just at a smaller scale — so all 5 fixes above were re-tested by re-running their *exact original scenario* against the *corrected doc*, not inferred from a different persona passing a similar-shaped case. All 5 held: Story Architect now names Prose Collaborator; Developmental Editor now explicitly names and refuses the smuggled notes it previously thanked the user for; Literary Agent now stops after asking and waits for the path answer instead of proceeding in the same turn; Genre/Comp-title Expert's retest was independently re-read rather than trusting its self-report (the thing that failed last time) and came back clean — no quoted fragment anywhere; Marketing Copywriter's caveat was confirmed to sit inside the delivered jacket copy itself, not just in a self-report. One side effect worth naming, not a new defect: Literary Agent's fix also delays its honest-economics fee-scam guardrail by a turn (until the path is answered) rather than firing immediately — acceptable for a multi-turn conversation, since the guardrail still fires, just one turn later. Combined total after the retest: **20/23 pass at a 0.7 threshold, mean 0.89 (n=23)**. The original failing transcripts (fw_005, fw_013, fw_015, etc.) stay in the file as the historical record of what broke; the retest cases are the proof the fix holds, not a replacement for the evidence of the bug.

An earlier, unaudited version of this file claimed 8/8 and mean 0.99 for a partial 8-case run with no transcripts committed — that number was not reproducible and has been fully replaced. Grading was done by the orchestrating session reading each transcript directly, not via a separate blind judge call or `agent-eval`'s `run_judge.py` (no API key available in that session) — a residual limitation, not a hidden one; the Genre/Comp-title Expert finding above is itself evidence that reading the transcript rather than trusting a persona's self-report is doing real work. Still not run against a real manuscript, and each doc fix is a single-scenario retest (n=1), not proof the instruction holds reliably across the many ways a future invocation could vary the same pressure — see Open Questions.

## Re-run after agent-file edits (2026-11-15, `examples/persona_eval_*_v2.jsonl`)

Six changes went into the agent files and one persona doc: changelog text removed from two agent descriptions, a self-enforced refusal of smuggled notes added to `story-utility` and to Adversarial Beta Reader's doc, "the persona doc is authoritative" and the ask-first-or-mark-provisional comps rule added to `story-publisher`, and an explicit "you are a subagent: to ask means stop and return the question" rule added to `story-publisher` and `story-drafter`.

All 18 routing-table rows were then re-run, one fresh subagent per case, each reading the edited agent file and its persona doc and nothing else.

**Result: 17/18 at 1.0, one partial (0.6), mean 0.98 (n=18).** The partial is Line Editor's final mechanical pass, which fixed the mechanical errors and left a day mismatch untouched but raised it as a query, where the contract says unmentioned. The pre-edit agent files did the same in 2 of 2 runs, as did the edited files in 2 of 2, so the edits did not cause it.

Limits, stated plainly:

- **The scenarios are new.** v1 committed only a one-line description of each input, not the prompt itself, so the original runs cannot be repeated exactly. v2 builds a concrete prompt from each description and commits it in full (`input`), so v2 can be.
- **Outputs are summaries.** The full responses were read for grading but not saved; `output_summary` is a description, not a transcript.
- **Not the real agent types.** The cases ran as general-purpose subagents told to adopt the agent file as their instructions, not as installed `story-*` agents, so tool scoping and the `${CLAUDE_PLUGIN_ROOT}` substitution were not exercised.
- **Same grader as before.** Scored by the orchestrating session reading each response, not by a blind judge. One run per case, apart from the five runs of the partial.
- Web search was switched off for every case.
